# SM-2-lite Karteikarten-Scheduling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das feste 5-Stufen-Leitner-Scheduling der Karteikarten durch ein einfaches, pro Karte adaptives Scheduling (SM-2-lite: Ease-Faktor + wachsendes Intervall, 3-Stufen-Bewertung, weicher 180-Tage-Cap) ersetzen.

**Architecture:** Eine einzelne Funktion (`grade()`) und ihre beiden Aufrufstellen (`answerCard()`, der globale Klick-Delegations-Handler) werden umgebaut; die Karteikarten-Rückseite bekommt einen dritten Bewertungsknopf. Alles bleibt innerhalb der bestehenden `S.srs`-Datenstruktur und des bestehenden Single-File-Aufbaus.

**Tech Stack:** Vanilla JS (keine Frameworks, ein HTML-File), Playwright/pytest für Tests (eigenes venv unter `~/.venvs/madina-app-tests`).

**Spec:** `docs/superpowers/specs/2026-11-23-srs-algorithm-design.md`

## Global Constraints

- Bewertungswerte: `0` = nicht gewusst, `1` = schwer gewusst, `2` = leicht gewusst.
- `EASE_START = 2.5`, `EASE_MIN = 1.3`, `EASE_MAX = 3.0` (jeweils geklemmt).
- Ease-Änderung je Bewertung: nicht gewusst `-0.2`, schwer gewusst `-0.15`, leicht gewusst `+0.15`. Nach jeder Änderung wird `ease` auf 2 Nachkommastellen gerundet (`Math.round(x * 100) / 100`), bevor geklemmt wird — sonst driftet der Wert nach vielen Wiederholungen durch Fließkomma-Ungenauigkeit (z. B. `2.95` würde sonst zu `2.9499999999999997`).
- Intervall für eine brandneue Karte (noch kein `ivl > 0`): schwer gewusst → `1` Tag, leicht gewusst → `4` Tage.
- Intervall für eine bestehende Karte (`ivl > 0`): schwer gewusst → `max(1, round(ivl * 1.2))`; leicht gewusst → `round(ivl * ease)` (mit der NACH dieser Bewertung aktualisierten Ease), beides geklemmt auf `IVL_CAP = 180` Tage.
- Nicht gewusst: `ivl = 0`, Karte sofort fällig (`d = now`), kommt in denselben bestehenden Fehler-Stapel-Mechanismus.
- `b` (Box-Level, nur noch für `knownCount()`s Schwelle `b >= 2` gebraucht) und der Fehler-Stapel-Austritt nach 2 aufeinanderfolgenden richtigen Antworten (`s >= 2`) bleiben unverändert in ihrer Bedeutung.
- Keine Migration alter `S.srs`-Daten nötig (Ridouane: aktueller Stand ist reine Testdaten).
- Keine Änderung an `startSession()`, `dueIds()`, `mistakeIds()`, `knownCount()`, der Sitzungs-Zusammenstellung oder dem Mistake-Pile-Requeue-Mechanismus (`s.queue.splice(Math.min(3, ...), 0, id)`).

## Review Focus

- Ease-Untergrenze: wiederholtes „nicht gewusst" darf `ease` nie unter `1.3` drücken.
- Ease-Obergrenze: wiederholtes „leicht gewusst" darf `ease` nie über `3.0` heben.
- Intervall-Cap: wiederholtes „leicht gewusst" darf `ivl` nie über `180` Tage wachsen lassen, auch nicht für einen einzelnen Rechenschritt.
- Fehler-Stapel-Austritt braucht genau 2 aufeinanderfolgende richtige Antworten, unabhängig davon ob „schwer" oder „leicht" — eine einzelne richtige Antwort nach einem Fehler darf die Karte noch nicht aus dem Stapel nehmen.
- Eine falsch beantwortete Karte muss innerhalb derselben Sitzung noch einmal auftauchen (nicht erst am nächsten Tag), unabhängig davon, wie hoch ihr Intervall vorher war.

def _force_due_and_regrade(page, served_app, book, topic_id, card_id, grade):
    stored = json.loads(page.evaluate("() => localStorage.getItem('madina-arabisch-v1')"))
    stored["srs"][card_id]["d"] = 0
    page.evaluate("(v) => localStorage.setItem('madina-arabisch-v1', JSON.stringify(v))", stored)
    page.reload()
    page.evaluate("() => { location.hash = 'karten'; }")

    page.click(f"[data-study='{topic_id}']")

    stored = json.loads(page.evaluate("() => localStorage.getItem('madina-arabisch-v1')"))

def test_interval_soft_caps_at_180_days_and_stays_there(page, served_app):
    c, card_id = _grade_first_card(page, served_app, 1, 'b1-l09', 2)  # ivl=4, ease=2.65
    c = _force_due_and_regrade(page, served_app, 1, 'b1-l09', card_id, 2)  # ivl=11, ease=2.80

def test_ease_floors_at_1_3_after_repeated_wrong_answers(page, served_app):
    c, card_id = _grade_first_card(page, served_app, 1, 'b1-l10', 0)  # ease=2.3
    for _ in range(5):  # -0.2 je Mal: 2.1, 1.9, 1.7, 1.5, 1.3
